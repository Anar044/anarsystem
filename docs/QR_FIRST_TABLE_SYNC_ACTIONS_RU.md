# Первый импорт столов QR из тестовой кассы — чек-лист

**Назначение:** безопасно проверить одну тестовую кассу Smart Horeca и получить из её iikoFront настоящий перечень залов и столов. Никаких заказов в iikoFront, кухонной печати, оплаты или действий с рабочими ресторанами на этом этапе.

## 0. Что уже сделано в коде

- Веб-приложение: `QR Menu → QR-заказы и столы → Столы и индивидуальные QR` показывает секции и столы выбранного POS-плагина, предлагает импорт новых активных столов. Старые QR-токены сохраняются при повторном импорте.
- Плагин: `GetRestaurantSections()` и `GetTables()` → `tablesSnapshot` на защищённый QR HTTPS API. Работает при `Enabled=true`, `AllowOrderCreation=false`, `AllowKitchenPrint=false`; старый Socket.IO адрес `http://68.233.120.197/plugin-websocket` не изменён.
- Сервер: принимает список только от плагина, прошедшего проверку по ключам и реестру для того же ресторана. До подтверждения preview D1 блокирует синхронизацию на уровне API.

## 1. Один раз — проверить отделение тестовой базы

В Cloudflare → Workers & Pages → существующий проект `smarthoreca` → Settings → Bindings **сравните фактические Database ID** двух привязок с именем `DB`: Production и Preview. Они должны быть **разными**. Production остаётся прежней (`anarsystem-db`), Preview должна использовать отдельную тестовую D1, например `anarsystem-qr-test` (имя пример, а не уже созданная база).

⚠️ Если Preview DB ещё совпадает с Production DB, **сначала** создайте отдельную тестовую D1 и привяжите её как Preview `DB`. Не включайте ничего до этой проверки. Переход на другую D1 означает, что в Preview может отсутствовать ранее опубликованное меню и приглашённые пользователи — это нормально; создайте/опубликуйте только тестовое меню, не копируйте боевую БД.

После проверки добавьте **только в Preview** переменную:

```text
QR_TEST_D1_ISOLATED=confirmed
```

Этот флаг — подтверждение администратора; сам по себе **не проверяет** Cloudflare D1 binding. Production-хосты не принимают `tablesSnapshot` и `syncPosTables`, даже если эту переменную ошибочно добавили туда.

## 2. Один раз — серверные секреты только в Preview

В Settings → Variables and Secrets создайте (значения — независимые криптографически случайные секреты, минимум 32 байта):

- `PLUGIN_INGEST_TOKEN` — для HTTP авторизации плагина (значение потребуется также в защищённом конфиге **тестовой** кассы);
- `QR_POS_BRIDGE_TOKEN` — второй независимый секрет POS Bridge (также в конфиге тестовой кассы);
- `QR_ORDER_RATE_SECRET` — отдельный секрет публичных QR-заявок на более позднем этапе;
- `SH_BACKEND_API_URL` — только при необходимости. Для выбора кассы из списка нужен работающий `/api/plugin/data`, который уже может быть настроен на данном preview.

Не публикуйте значения в GitHub/браузерном JS/чат. Не изменяйте Production Variables и основной Socket.IO адрес. После изменения привязок/секретов используйте **новый Preview deployment** и убедитесь, что новые значения применились.

## 3. Подключить новую сборку только к тестовой кассе

1. Закройте тестовый iikoFront, сохраните всю прежнюю папку `Plugins\\KassaSH` и локальный `smarthoreca.json`. Не оставляйте дубли DLL в каталоге `Plugins`.
2. Замените только тестовую сборку из PR #4; если скачанный ZIP Windows пометил как сетевой, в свойствах ZIP нажмите **Разблокировать** перед извлечением.
3. В уже существующем **защищённом локальном** `smarthoreca.json` добавьте блок `QrPosBridge` (не переписывайте `PluginId`, `DepartmentId`, `SocketAuthSecret`):

```json
"QrPosBridge": {
  "Enabled": true,
  "AllowOrderCreation": false,
  "AllowKitchenPrint": false,
  "Url": "https://feature-qr-order-internal-co.smarthoreca.pages.dev/api/qr-menu/pos-bridge",
  "PluginIngressToken": "ЗНАЧЕНИЕ_ИЗ_PREVIEW_PLUGIN_INGEST_TOKEN",
  "BridgeToken": "ЗНАЧЕНИЕ_ИЗ_PREVIEW_QR_POS_BRIDGE_TOKEN",
  "PollSeconds": 10
}
```

Это **фрагмент** существующего JSON, а не самостоятельный файл. Убедитесь, что `QrPosBridge.Url` указывает именно на актуальный HTTPS Preview, не на боевой Socket.IO. В диагностическом режиме `OperatorPin` не нужен.

4. Запустите iikoFront. Ожидаемые безопасные сообщения:
```text
SocketIOFactory ... auth=hmac-sha256-v1
QrPosBridge :: diagnostics only ...
QrPosBridge :: HTTPS diagnostic handshake accepted; no POS writes or kitchen printing.
QrPosBridge :: POS table catalog synchronized (N tables; no POS writes).
```
Если вместо последней строки `QR Bridge HTTP 409`, проверьте Preview D1 и её подтверждение; если 401 — пару тестовых секретов, если 403 — точность `PluginId`/`DepartmentId` и регистрации, если 502 — backend plugin registry. **Не включайте создание заказов для обхода ошибок.**

## 4. Импорт в Smart Horeca

Откройте тестовый QR Menu → «QR-заказы и столы». Убедитесь, что опубликовано меню нужного тестового ресторана. Сохраните выбранную тестовую кассу при **выключенной** галочке `Разрешить гостям оформлять QR-заказы`. Синхронизированный каталог появится внутри «Столы и индивидуальные QR».

Выберите нужные активные столы по залам → «Добавить выбранные столы». Каждый новый POS GUID получает уникальную URL-ссылку QR; уже импортированные столы сохраняют прежний токен. **Не включайте гостевые заказы и кухонную печать на этом этапе.**

Результат: в Smart Horeca должны отображаться реальные залы и столы тестового iikoFront, а все QR-оплаты и POS создания заказов должны оставаться отключены. Перед переходом к заказам потребуется отдельная сквозная проверка.
