# QR Menu — автоматический импорт столов в существующую D1 Smart Horeca

**Режим:** общая Cloudflare D1 `anarsystem-db`; отдельная D1 не требуется. Код — в тестовой ветке `feature/qr-order-internal-core-20261029`, **не** в `main`.

## Зачем ограничения, если база одна

Синхронизация столов сохраняет данные в отдельных QR-таблицах `qr_pos_table_snapshots` и `qr_order_tables` внутри **уже используемой** D1. Существующие POS-заказы, остатки и данные других ресторанов не должны изменяться. Разделение выполняется по `restaurant_id + plugin_id` и правам Smart Horeca `qr.manage`. Это не отдельная БД и не пробное копирование боевой БД.

При работе в общей D1 на первом этапе сервер **запрещает гостевое оформление QR-заказов и все POS действия**, независимо от состояния кассы, оставляя только diagnostic hello и read-only получение каталога столов. Без явного разрешения конкретной тестовой кассы каталог не записывается в D1.

## 1. Настройка Preview без новой D1

Оставьте Preview проекта `smarthoreca` на той же существующей привязке `DB`, которую планируете использовать. **Не создавайте новую D1, не сбрасывайте и не очищайте рабочую базу**. Если Preview `DB` ещё не настроен, это нужно установить в Cloudflare Workers & Pages → Pages project → Settings → Bindings. До изменения привязки сначала проверьте фактический database ID.

В Settings → Variables and Secrets → **Preview** укажите четыре переменные:

```text
QR_TABLE_SYNC_MODE=shared-test
QR_TABLE_SYNC_PREVIEW_HOST=feature-qr-order-internal-co.smarthoreca.pages.dev
QR_TABLE_SYNC_DEPARTMENT_ID=28a38f52-9b1b-01a7-019f-8455da3a0010
QR_TABLE_SYNC_PLUGIN_ID=0638669c-67e2-4f14-be2d-567404352a7c
```

Последние два идентификатора взяты из прежнего тестового скриншота; **проверьте их соответствие выбранной сейчас тестовой кассе**. В случае смены тестового ресторана/кассы нужно изменить разрешения, не подставлять UUID другого ресторана автоматически. Хост вводится без `https://` и без пути.

Это серверные настройки; не создавайте их на Production. Старый флаг `QR_TEST_D1_ISOLATED` **не требуется** в режиме `shared-test`.

Два независимых защищённых секрета по-прежнему нужны для QR HTTPS API, **только в Preview**:
- `PLUGIN_INGEST_TOKEN` (тот же, что `QrPosBridge.PluginIngressToken` на тестовой кассе);
- `QR_POS_BRIDGE_TOKEN` (тот же, что `QrPosBridge.BridgeToken` на тестовой кассе).

`QR_ORDER_RATE_SECRET` понадобится позже для гостевых заказов; для импорта столов в `shared-test` он не нужен. Если реестр плагинов не отвечает, проверьте доступность backend `/api/plugin/data` (не подменяйте это URL существующим `/plugin-websocket`).

После настройки выполните новое Preview-развёртывание тестовой ветки. Изменения в `main` делать не требуется. Изменения переменных/привязок применятся к соответствующему deployment, а не к уже работающему старому процессу.

## 2. Тестовая касса

Установите только на **тестовый** iikoFront ZIP `SH_QR_POS_TABLE_SYNC_SAFE_2026-10-30.zip` с резервным копированием старой папки `KassaSH`. Не изменяйте работающие кассы.

В существующем защищённом `smarthoreca.json` оставьте прежние `PluginId`, `DepartmentId`, `SocketAuthSecret`; добавьте или настройте:

```json
"QrPosBridge": {
  "Enabled": true,
  "AllowOrderCreation": false,
  "AllowKitchenPrint": false,
  "Url": "https://feature-qr-order-internal-co.smarthoreca.pages.dev/api/qr-menu/pos-bridge",
  "PluginIngressToken": "СЕКРЕТ_ИЗ_PREVIEW_PLUGIN_INGEST_TOKEN",
  "BridgeToken": "СЕКРЕТ_ИЗ_PREVIEW_QR_POS_BRIDGE_TOKEN",
  "PollSeconds": 10
}
```

Это фрагмент JSON, а не самостоятельный `smarthoreca.json`. `OperatorPin` не нужен, потому что новые заказы и кухонная печать выключены.

В логах ожидать:
```text
QrPosBridge :: HTTPS diagnostic handshake accepted; no POS writes or kitchen printing.
QrPosBridge :: POS table catalog synchronized (N tables; no POS writes).
```

Если HTTP 403: проверьте `departmentId`, `pluginId`, `QR_TABLE_SYNC_PREVIEW_HOST` и регистрацию кассы на сервере.
Если HTTP 401: проверьте два тестовых секретных ключа.
Если HTTP 409: проверьте разрешения для общей D1 и что плагин не пытается включить создание заказов.
Если HTTP 502: проверьте доступность реестра плагинов.
Для сохранения данных не включайте `AllowOrderCreation` и `AllowKitchenPrint` ради устранения ошибки.

## 3. В самой Smart Horeca

Откройте **QR Menu → QR-заказы и столы**, выберите тестовый ресторан и кассу, галочку оформления заказов **не включайте**. Нажмите «Сохранить режим», затем «Обновить список с кассы». Выберите активные столы по залам и «Добавить выбранные столы».

- Существующий POS GUID не создаётся повторно; ранее выданные QR-токены остаются прежними.
- Импорт по чужому ресторану, чужой кассе, производственному домену или без явных разрешений заблокирован.
- Данные в D1 хранятся в отдельных QR-таблицах; никакой автоматической очистки.
- В рамках этой стадии QR-заказы, фискальное закрытие и печать кухни не выполняются.

**Ограничение:** у меня нет прямого доступа к настройкам Cloudflare и локальному тестовому iikoFront. Коммиты и GitHub CI не подтверждают фактический импорт на вашей кассе; это проверяется только по новому логу и списку столов в интерфейсе.
